# PHP Website removal ordering

An exclusively owned PHP-FPM pool must retire before its Website document root or Unix identity is deleted. Otherwise a subsequent shared FPM reload references the deleted `chdir` directory and can stop unrelated PHP pools and file managers.

The cleanup adapter uses the exact Website/Application/Unix provisioning journal and its durable creation receipt. It passes the original provisioning intent separately from the Website's current registered PHP settings. Identity and document root must still match; the current pool must be a root-owned regular file with the exact rendered content and mode. Any pool for the same Unix identity in another supported PHP version blocks removal.

Retirement freezes the current configuration digest in a private durable deletion checkpoint before unlink. It removes the current pool, validates and reloads its shared FPM service, waits for the socket listener to leave and verifies every supported version pool and the socket are absent. It never compensates a settings/version update by recreating an older pool. A restart resumes the same checkpoint; a changed target or a pool reappearing after retirement is blocked. Unix cleanup repeats the physical checks before removing the identity.

Source regressions cover settings and version changes, failed reload/restart recovery, binding and pool drift, sibling preservation and listeners without socket files. An isolated `.28` test changed maxChildren from 8 to 9 through the installed PHP UI, retired that pool with the current source adapter from a temporary test directory, replayed the same retirement, preserved sibling HTTP and removed both fixture sites through the normal panel. This is not acceptance of a newly deployed package. Full packaged removal after settings/version changes, physical version-transition retirement, imported pools and PHP sites with database or mail dependencies remain open.

SFTP bind mounts and OpenSSH Match rules must retire first, using the exact original receipt. An enabled mount unit can recreate a deleted home directory on reboot. Physical retirement checks configuration, chroot, systemd unit and the actual mount inventory; a compensated receipt alone is insufficient. The key-aware production handler must preserve these retirement methods.
