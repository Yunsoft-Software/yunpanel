# Terminal security and runtime

YunPanel exposes a real PTY, not a one-shot HTTP command endpoint. The browser first sends an authenticated, CSRF-protected `POST /api/panel/terminal/capabilities` for exactly one local Server or Website. The response contains a random 30-second, single-use capability bound to the current session and user. Only its SHA-256 digest exists in backend memory. Capabilities are never accepted in a URL or query string.

The web gateway upgrades only exact `/api/terminal` for an allowlisted client IP and the configured Origin. It removes caller-supplied forwarding and authorization headers, then supplies its authenticated internal proxy identity. The API repeats peer, cookie, exact Origin, Owner-role and current Owner-MFA validation. The selected WebSocket protocol is `yunpanel-terminal-v1`; the one-time capability travels as a second protocol value and is consumed before PTY creation.

Server terminals are fixed to `root` at `/root` and require the packaged root API service. Site terminals are available only for static/Node Websites with a deterministic `yunapp-*` identity and managed `current` path. The backend resolves that symlink and requires it to point at an exact UUID release beneath the same application root. It launches fixed `/usr/sbin/runuser -u <site-user> -- /bin/bash --noprofile --norc -i` arguments so the shell receives the account's real Unix group context. No caller command or executable is accepted. PTY environments are a fixed, secret-free allowlist rather than the control-plane service environment.

The JSON WebSocket protocol accepts only input text, resize dimensions and ping. Output is returned as plain terminal text for xterm.js; it is never interpreted as HTML. Ctrl+C, Ctrl+D, Unicode, resize and full-screen terminal programs therefore use the PTY's native control stream. The browser opens the socket only after an explicit Owner action, displays the exact user and working directory returned by the backend, and closes it on route/component disposal. Reconnect always creates a new capability and PTY; disconnected processes are not retained.

Default server limits are five concurrent terminals per Owner, twenty globally, 15 minutes without client input/resize/ping, four hours absolute lifetime, 16 MiB output per session, 1 MiB pending WebSocket output and 16 KiB per input message. Disconnect, invalid messages, limits, service shutdown and auth revocation terminate the whole PTY process group with SIGHUP followed by bounded SIGKILL cleanup.

The common audit store records accepted/succeeded/failed open events and close reason against the Server or Website. Raw keystrokes, terminal output and shell history are never copied into common audit. Logout, logout-all, session deletion/expiry, password change, MFA changes/reset, role change, user disable and user deletion all use the same live-session revocation registry.

`node-pty` is a pinned and explicitly approved native dependency. Debian build output is architecture-specific (`amd64` or `arm64`), may only be built on matching Linux, and fails before packaging if the native module cannot load.
