# DNSSEC rollover adapter ilerlemesi — 2026-09-17

PowerDNS DNSSEC host adapter'ı rollover için secret-safe ve optimistic-concurrency korumalı cryptokey primitive'leri kazandı.

- Inspect yalnız cryptokey collection'ın public alanlarını okur; private key içerebilen tek-key endpoint'i kullanılmaz. PowerDNS yanıtında `privatekey` bulunsa bile public state'e taşınmaz.
- Normalize edilmiş public key kümesi deterministik SHA-256 `keySetDigest` üretir. Duplicate key ID, malformed DS/algorithm/bits ve stale preview state'i mutation'dan önce reddedilir.
- KSK/CSK create yalnız `keytype`, `active`, `published`, `algorithm` ve `bits` gönderir; private key content kabul etmez. Baseline key ID kümesi ve digest, lost-ack retry'da yeni anahtarı yeniden gözleyerek ikinci key üretimini engeller.
- Publish/activate/deactivate primitive'i exact before/after digest'leriyle çalışır. Hedef state'e ulaşılmış belirsiz mutation restart/retry'da yeniden doğrulanıp rectification tamamlanır.
- Delete primitive'i exact remaining-key digest'i gerektirir ve başka bir active+published DS taşıyan key yoksa fail-closed kalır. Lost-ack delete yeniden gönderilmeden authoritative key koleksiyonuyla uzlaştırılır.
- Publish/activate/deactivate ve delete adımlarının hedef/remaining key-set digest'lerini üreten salt-okunur host preflight'ları aynı canonical PowerDNS public-key algoritmasını kullanır; API runtime'ın digest algoritmasını kopyalaması gerekmez ve preview sırasında provider mutation oluşmaz.
- Her cryptokey mutasyonu sonrasında zone rectification ve public collection post-condition kontrolü zorunludur.
- Rollover preflight yalnız mevcut durum `secure_ready`, public key-set digest'i geçerli, parent DS kümesi tek active+published KSK/CSK'ye bütünüyle bağlı ve başka KSK/CSK artığı yoksa apply'e izin verir.
- Preflight seçilen eski key kimliği ile aynı algorithm/bits yeni-key hedefini ve create→publish→DNSKEY propagation→activate→parent DS addition/retirement→old-key cleanup aşamalarını preview digest'ine bağlar. Authenticated GET preview endpoint'i salt-okunurdur ve private materyal taşımaz.
- Ayrı rollover operation registry v4 bu aşamaları root-private atomik store'da yalnız kontrollü state geçişleriyle tutar. Exact preview/key/parent identity korunur; mutation intent aşamalarında current ve target key-set digest'leri ayrı saklanır, böylece lost-ack retry unrelated key drift'ini hedef state sayamaz. Yeni key ID/DS/digest kanıtı yokken publish sonrası, exact serial/DNSKEY/TTL propagation kanıtı yokken activation sonrası ve parent DS TTL kanıtı yokken old-key mutation aşamaları persisted edilemez. Güvenle tamamlanabilen v1-v3 journal state'leri v4'e yeniden yazılır; eksik destructive kanıt uydurulması gereken ilerlemiş legacy state fail-closed kalır.
- Aynı aşama/evidence retry idempotenttir; aşama atlama ve farklı evidence çatışması reddedilir. Confirmation diskte kalabilir fakat public operation görünümüne çıkmaz; terminal result yalnız old/new key ID, final public key-set digest, serial ve parent DS taşır.
- Control-plane service bridge create/state/delete ve salt-okunur target-digest çağrılarını exact local root Domain üzerinden çözer; PowerDNS API credential'ı her çağrıda encrypted registry'den materialize edilir, runtime input/result/journal'a eklenmez.
- İlk durable runtime dilimi exact confirmed preflight'ı journal'a alır, `creating_key` intent'ini provider çağrısından önce persist eder, yeni KSK/CSK'yi inactive+unpublished üretir, publish current/target digest'lerini `publishing_key` intent'ine yazar ve key'i inactive+published hale getirir.
- Create veya publish provider cevabı kaybolursa operation ilgili mutation intent'inde kalır; restart/retry host adapter'ın exact baseline/target post-condition'ıyla sonucu uzlaştırır ve duplicate key/mutation üretmez. Runtime publish sonrasında `verifying_dnskey_propagation` aşamasında durur; secondary/TTL kanıtı olmadan activation, parent DS veya old-key cleanup yapmaz.
- Production composition rollover runtime'ını ayrı `dnssec-rollover-operations.json` root-private store'una bağlar; yol `YUNPANEL_DNSSEC_ROLLOVER_OPERATION_STORE` ile açıkça değiştirilebilir. Strict `previewDigest` + typed confirmation alan authenticated apply endpoint'i `202` operation döndürür; Domain-scoped list/get endpoint'leri confirmation veya provider credential yayınlamaz ve başka Domain'in operation'ını gizler.
- DNSSEC preview/apply ile rollover apply ortak management audit sınıflandırmasına alındı. `202` rollover cevabı yalnız accepted audit üretir; terminal başarı henüz propagation/parent/cleanup tamamlanmadan yazılmaz. Route-parity testi DNSSEC HTTP kaynağını da tarar ve yeni unaudited mutation eklenmesini engeller.
- Host runtime salt-okunur DNSKEY propagation inspector'ı primary ve tanımlı bütün secondary IP'lerde TCP authoritative SOA+DNSKEY sorgusu yapar. Yalnız exact publication serial ve exact yeni public DNSKEY her uçta görülürse TTL hesabı açılır; journaled publication zamanından gözlenen en yüksek DNSKEY TTL kadar süre geçmeden ready olmaz. Timeout, non-authoritative cevap, serial drift ve missing key fail-closed kalır; process error mesajı veya key dışı cevaplar public evidence'a taşınmaz.
- Control-plane propagation bridge güncel public key-set digest, publication serial, yeni key ID/DS/DNSKEY ve DNS identity target'larını yeniden doğrular. Runtime hazır olmayan gözlemi mutation yapmadan `verifying_dnskey_propagation` durumunda bırakır; hazır gözlemde publishedAt/TTL/eligibleAfter/checkedAt/targetCount kanıtını ve host adapter'ın exact activation target digest'ini journal `activating_key` intent'ine yazar.
- `activating_key` intent'i current/target key-set digest, inactive+published source state ve active+published hedef state ile host adapter'a bağlandı. Activation cevabı kaybolursa journal intent'te kalır; restart/retry exact target digest'i yeniden gözleyerek ikinci mutation üretmeden kapanır. Başarılı activation yeni serial ve key-set digest'i persist edip yalnız `awaiting_parent_ds_addition` durumuna geçer; parent DS'yi örtülü değiştirmez.
- Parent addition gözlemi güncel local key-set digest ve root Domain kimliğini yeniden doğrular. Yalnız parent authoritative DS kümesinde eski key'e ait en az bir DS ile yeni key'e ait en az bir DS birlikte bulunuyor ve bu iki key dışında yabancı DS yoksa operation `awaiting_parent_ds_retirement` durumuna ilerler. Eksik, absent, unverifiable veya foreign DS state mutation yapmadan bekler; eski key henüz değiştirilmez.
- Parent retirement gözlemi aynı local key-set/domain fence'ini yeniden uygular. Eski key'e ait hiçbir DS kalmamış, yeni key'e ait en az bir DS mevcut ve foreign DS yoksa canonical parent DS kümesi, authoritative RRset TTL'i, ilk gözlem zamanı ve hesaplanan son bekleme zamanı journal v4 `waiting_parent_ds_ttl` aşamasına persist edilir. Süre dolduktan sonraki yeni authoritative gözlem aynı clean new-only DS durumunu yeniden kanıtlamadan host adapter'ın exact inactive+published old-key target digest'i hesaplanmaz ve `deactivating_old_key` intent'ine geçilmez.
- Parent DS inspector v3 authoritative parent nameserver cevaplarındaki canonical DS kayıtlarına ek olarak en uzun RRset TTL'ini bounded public evidence olarak taşır; absent/unverifiable state'te TTL `null` kalır. DNSSEC public state bu TTL'i açığa çıkarır. Process restart ilk gözlem ve deadline'ı kaybetmez. TTL beklenirken old DS yeniden görünür, foreign DS belirir, yeni DS kaybolur veya parent state doğrulanamaz hale gelirse persisted gate sıfırlanıp yeniden `awaiting_parent_ds_retirement` aşamasına dönülür; sonraki clean gözlem için tam TTL baştan beklenir.
- `deactivating_old_key` intent'i çalıştırılmadan hemen önce parent state yeniden okunur; yalnız new-key DS, foreign/old DS yokluğu ve tamamlanmış TTL kanıtı sürüyorsa eski key active+published durumundan inactive+published durumuna exact current/target key-set digest ile geçirilir. Provider cevabı kaybolduktan sonra restart aynı target digest'i gözleyip ikinci state mutation üretmeden uzlaştırır. Başarılı deactivation sonrasında old key'in exact public kimliği ve active new key yeniden doğrulanır, salt-okunur remaining-key digest'i `deleting_old_key` intent'ine persist edilir; DELETE bu dilimde çalıştırılmaz.
- `deleting_old_key` intent'i çalıştırılmadan parent state ve local key-set digest yeniden fence'lenir. DELETE exact deactivated/remaining digest çiftiyle yürür; cevap kaybolursa restart old key'in yokluğunu ve remaining digest'i gözleyerek duplicate DELETE üretmez. Terminal `succeeded` yalnız old key'in yok, yeni key'in exact active+published ve parent'ın yalnız journaled new-key DS kümesinde olduğu doğrulanınca bounded old/new key ID, final digest, serial ve parent DS sonucuyla yazılır.

Bu dilim host mutation, preflight, journal, create→publish→propagation→activate→parent addition/retirement+TTL→deactivate→delete runtime'ı ve terminal completion'ı tamamlar. Dış registrar adımlarından sonra operation ID ile açık operator continuation yüzeyi `plan.md` içinde açık kalır; gerçek PowerDNS ve process-kill kabulü `todo.md` T-DNS kapsamındadır.
