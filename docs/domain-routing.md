# Domain routing lifecycle

Domain canonical-hostname, alias, managed-HTTPS, redirect and per-site Nginx settings are revisioned desired state. An Owner first sends `POST /api/domains/:domainId/update-preview` with an exact `changes` object and then applies the same changes through `PATCH /api/domains/:domainId` with the preview SHA-256 and its full typed confirmation. Unknown fields, no-op requests, stale revisions, hostname conflicts, invalid parent relationships and active Domain/certificate jobs fail before mutation.

The editable fields are `primaryDomain`, `aliases`, `httpsMode`, `httpsRedirect`, `canonicalRedirect` and `nginxSettings`. Hostnames use the existing IDN-to-ASCII canonicalization and global ownership checks. `httpsRedirect` is valid only with managed HTTPS. Switching to managed HTTPS defaults it on unless explicitly disabled; switching HTTPS off disables it. `canonicalRedirect` redirects every alias to the primary hostname while preserving the request URI. Before a certificate exists, canonical HTTP redirects remain HTTP so the primary server can continue serving the ACME challenge. Once TLS is attached, aliases redirect to the primary hostname on both HTTP and HTTPS, and the primary HTTP listener follows the explicit HTTPS-redirect policy.

`nginxSettings` is target-specific and normalized into the preview rather than accepting raw Nginx text:

- Common: nullable `clientMaxBodySizeMb` from 1–1024 and up to 12 explicit response `headers`.
- Proxy: nullable `proxyTimeoutSeconds` from 1–600 and boolean `websocket`.
- Static: boolean `spaFallback` and nullable `staticAssetCacheSeconds` from 0–31,536,000; zero emits a no-store policy and null emits no asset-cache directive.

Each response header has exact `name`, `value` and `always` fields. Names are bounded and case-insensitively unique. Control/newline characters, Nginx variable expansion, quote/backslash injection and protocol-owned headers such as `Set-Cookie`, `Content-Length`, `Connection` and `Cache-Control` are rejected. Header values are ordinary published configuration, not a secret store. The preview reports the complete current/next normalized settings and exact changed field names.

Applying an update increments the desired revision and clears the staged revision. WebSocket and SPA values remain mirrored in the target metadata for compatibility but the normalized `nginxSettings` object is the staged configuration contract. A hostname-set change or disabling HTTPS detaches the old certificate from the Domain; ordinary Nginx-setting changes do not. The Domain must be staged and activated again. Activation atomically installs the generated candidate, runs `nginx -t`, reloads Nginx and restores the previous working file on validation/reload failure. If the canonical hostname changed, both old and new filenames participate in that rollback. Durable recovery requires the exact rendered checksum to be active and the previous filename to be absent before marking the revision applied.

After a hostname change, a new managed certificate may replace the detached production record. The old record remains active until replacement issuance succeeds, then becomes `superseded` and is excluded from renewal. An Owner may also import matching custom material or select a prior usable certificate through the guarded flow in `docs/certificate-selection.md`. Certificate reconciliation verifies that the exact current primary hostname and aliases match the issued certificate before attachment. Nginx staging re-opens local certificate material, checks hostname coverage, validity, fingerprint and certificate/private-key identity, so stale, replaced or mismatched material cannot enter a TLS config.

Every public Domain response contains a bounded `diagnosis` or `null`. Desired/staged/applied drift produces explicit stage or activation actions; missing managed TLS asks for a covering certificate; known Nginx failures map to authored remediation. Raw Nginx output, filesystem paths, certificate keys and arbitrary error text/codes are not copied into the diagnosis. Persisted Domain store versions 1 and 2 are hydrated with their exact legacy redirect, target and applied canonical behavior in memory, then written as version 3 only on a later mutation.

The common management audit records only Domain-scoped preview/apply identities and outcomes. Source tests cover request validation, migration, stale previews, concurrent job refusal, Nginx rendering/rollback, activation recovery, certificate replacement and protocol payloads. Real packaged Ubuntu, Nginx, DNS and browser/curl acceptance remains in `todo.md`; source tests are not host evidence.
