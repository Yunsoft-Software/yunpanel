# T803 — KRİTİK WEB-01: Bayi site tahsisi (AllocateSiteDialog) kilitli ve sihirbazla açılan sitelerin silinmesi domain_removal_not_ready ile bloke oluyor
Yapan: AGENT_4 · Teslim: 2026-10-27 10:19

## Yapılanlar
1. **Bayi Site Tahsisi / Customers & Resellers Rota Kaynakları ve Şema Düzeltmesi:**
   - `apps/web/src/workspace/workspace-resources.js` içinde `/customers` ve `/resellers` rotalarına `domains`, `websites` ve `servers` kaynak koleksiyonları eklendi. Böylece `AllocateSiteDialog` içinde `serverId` ve `domains` boş kalmayıp yerel sunucu doğru yüklendi.
   - `apps/web/src/workspace/ResellerCustomersPage.jsx` içinde `AllocateSiteDialog.handlePreview` fonksiyonunda `site-create-base.js` şemasıyla uyumsuz olan `displayName`, `aliases`, `dnsMode` ve `mailMode` alanları temizlendi. Bunun yerine `name: cleanDomain`, `source: { type: 'starter' }`, `database: { mode: 'none' }`, `mail: { mode: 'local' }`, `dns: { mode: 'local' }` geçerli payload yapısı gönderildi.
2. **Subdomain Paylaşımlı Dosya Kökü Çözümlemesi:**
   - `apps/web/src/workspace/new-website-form.js` içinde `resolveSubdomainSharedFileRoot` fonksiyonu ana website nesnesinin/belge kökünün (`parentWebsite`) iletilebilmesine uygun hale getirildi; leaf dizinleri (`httpdocs`, `public`, `current`) ayıklanıp `/var/www/vhosts/<parent>/subdomains/<subdomain>` standart yapısına uygun bağlandı.
3. **Domain / Website Silme Blokajlarının Çözümü:**
   - `apps/api/src/domain-removal-plan.js` içinde `database_binding_dependencies_present` engeli `ORCHESTRATABLE_IMPACT_BLOCKERS` ve `retainedBucket` içine dahil edildi. Bir website'a bağlı domain silinirken veritabanları website removal motoru tarafından adım 004'te temizlendiğinden dolayı domain removal aşamasında sahte hardBlocker üretmesi önlendi.
   - `apps/api/src/domain-removal-plan.js` içinde `dns_zone_parent_ds_unverifiable` engeli `ORCHESTRATABLE_DNS_BLOCKERS` içine eklendi; DNSSEC üst DS kaydı doğrulanamayan yerel/özel test alanlarında domain silme akışının `domain_removal_not_ready` ile tıkanması engellendi.
   - `apps/api/src/dns-zone-retirement.js` içinde `captureDeletionSnapshot` ve `deleteCapturedSnapshot` metotlarında DS varlığı kontrolü `if (parentDs.status !== 'absent')` yerine `if (parentDs.status === 'present')` olarak düzeltildi; `unverifiable` durumu DS varlığı sayılarak hata fırlatılması engellendi.
4. **Testler:**
   - `apps/web/test/workspace-resources.test.js`: `/customers` ve `/resellers` kaynak gereksinimleri test edildi.
   - `apps/web/test/reseller-customer-panel.test.js`: `AllocateSiteDialog` payload yapısının `site-create` şemasına tam uyumu doğrulandı.
   - `apps/api/test/domain-removal-plan.test.js`: `database_binding_dependencies_present` ve `dns_zone_parent_ds_unverifiable` senaryoları için birim testler eklendi.
