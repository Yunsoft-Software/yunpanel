## Yapılanlar
- BAK-05 özelliği için `e2e/ozellik/bak-05.spec.js` senaryosu gerçek panele, gerçek API'ye ve canlı test sunucusuna (`yunpanel-test`) karşı sıfır mock/stub ile yazıldı.
- Mutlu yol:
  - Sunucu arayüzünde (`/servers` -> Tanılama ve yazılım bilgileri) "Yedekleme ve depolama" bölümünde `restic` yedekleme motoru, `rclone` uzak depolama motoru (S3, B2, Google Cloud, SFTP desteği) ve `/var/lib/yunpanel/backups` yerel deposu doğrulandı.
  - Canlı API üzerinden Rclone S3 uzak depolama hedefi (`POST /api/panel/backups/remotes`) oluşturuldu; hassas kimlik bilgilerinin AES-256-GCM ile şifrelenip API yanıtında maskelendiği teyit edildi.
  - Rclone uzak depolama hedefine bağlı Restic deposu (`backend: rclone`, `target: remote:bucket/path`) oluşturuldu.
  - Yerel Restic deposu (`backend: local`, `initialize: true`) oluşturuldu ve başlatıldı.
  - Web sitesi Yedekleme arayüzünde (`/websites/:id/backup`) "Uzak depo (rclone)" durum satırının bağlandığı, Depo listesinde Yerel ve Uzak depoların kartlarının görüntülendiği, Yerel depoda "Sağlık Denetimi" butonunun aktif olduğu ve "Plan ve Zamanlama" modalında depoların seçilebilir olduğu doğrulandı.
  - SSH ile sunucu üzerinde `rclone-remotes.json` (AES-256 ciphertext/iv/tag), `restic-repositories.json` ve disk üzerinde `/var/lib/yunpanel/backups/restic/repos/:id/config` fiziksel dosyası kanıtlandı.
- Hatalı girdi: Desteklenmeyen remote türü (`type: 'ftp'`) reddi (400 `rclone_remote_type_unsupported`), geçersiz karakterli isim reddi (400 `rclone_remote_name_invalid`), rclone için eksik target reddi (400 `restic_target_invalid`), kısa parola reddi (400 `restic_password_invalid`) ve unauthenticated istek engellemesi (401/403) doğrulandı.
- Plesk eşdeğerliği: Plesk Backup Manager'daki "Remote Storage Settings" (FTP Storage, Amazon S3, Google Drive vb.) arayüz formunun YunPanel UI üzerinde bulunmayıp yalnızca API seviyesinde rclone remotes desteklendiği tespit edildi ve `test.fail` ile işaretlendi.
- Sıfır artık ilkesi: `afterAll` hook'unda oluşturulan tüm uzak hedefler, uzak depolar ve yerel depolar API üzerinden silindi; disk üzerindeki yerel repo dizini SSH ile temizlendi ve disk kontrolüyle 0 artık doğrulandı.
