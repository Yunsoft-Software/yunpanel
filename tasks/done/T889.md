## Yapılanlar

Bu teslim yalnız mevcut native24 testinin tanılama kanıtını tamamlar. Native24 q3, 94.26 saniyede normal create HTTP409 yüzünden başarısızdı: üç gerçek PHP oluşturma/readiness/ilk dinamik200 geçti, dördüncü POST geçerli receipt vermeden409 döndü. Mevcut callback JSON hatasını okumadan status assertion yaptığından kod bilinmiyordu. Önceki koşunun dört exact fixture temizliği ve original canonical TLS200 kontrolleri geçti; depolanan gözlemler true→true idi. Bu bulgu preview, kilit veya PHP runtime nedenine atanmıyor.

Normal create response artık tam bir kez JSON parse edilir. `proof.createResponses[]` her gerçek status, JSON parse sonucu, yalnız bounded lowercase identifier karakterleriyle izin verilen `error.code`, persisted ledger key/run/operation/provisioning ve Website/Application/Domain/Server UUID kimliklerini kaydeder. Ledger private/no-symlink, run eşleşmesi, mevcut input/preview operation identity ve UUID kontrollerinden geçer. Kanıt private dosyaya mevcut strict status assertion ve tanılama GET'inden önce yazılır.

Yalnız status200/201 dışında, persisted provisioningId (yoksa aynı persisted operationId) ile normal provisioning GET'i bir kez okunur; 10s timeout, redirect0, retry yok. Tanılama; GET status/error-code/parse/transport booleans, operation presence ve exact operation/Website identity eşleşmesi booleans ile sınırlıdır. Eşleşen kayıtta enum operation/step state ve yalnız gerçek preview planında bulunan step ID'leri, required boolean ve bounded step error-code tutulur. Raw body, response message, header, cookie, environment veya credential kaydedilmez. Tanılama hatası create başarısızlığını PASS yapmaz.

Orijinal `[200,201]` strict beklenti güvenli error-code ipucuyla aynen sürer. POST tekrarı yok. Başarılı dönüş aynı tek parse edilen body.data'dır. Wave/barrier, causal false→true, ilk dinamik200, TLS, özgün/diğer sitelerin korunması, tüm cleanup ve deadline beklentileri değiştirilmedi. Ürün kaynakları ve protected readiness probe değiştirilmedi.
