- Senaryolar:
  1. Mutlu yol: Web siteleri kart rozetleri (`ws-badge` kalan gün rozeti), SSL sekmesi detayları (`Sertifika adı`, `Kapsam`, `Başlangıç`, `Bitiş`, `HTTPS tercihi`), Bildirim ve Görev Merkezi (`Sistem Uyarıları` sekmesi) ve fiziksel TLS doğrulaması (Node `tls.connect` ile Nginx `:443` portuna SNI TLSv1.3 el sıkışması, SSH üzerinden `openssl s_client` X.509 SHA-256 fingerprint karşılaştırması ve panel API `verify-tls` uç noktasında `matches: true` kanıtı).
  2. Hatalı girdi ve sınırlar: UI'da geçersiz e-posta formatlarında buton kilitlenmesi (`disabled: true`), API seviyesinde aktif olmayan domainde `409 http_domain_not_active`, geçersiz request gövdesinde `400 invalid_certificate_request`, HTTP-01 wildcard talebinde `409 wildcard_not_supported`, canlı sunum uyuşmazlığında `reason: "fingerprint_mismatch"` ve `reason: "valid_to_mismatch"`, ve kısmi servis reload (`certificate_reload_partial`) durumunda sertifikanın `active` kalarak teşhis üretmesi.
  3. Güvenlik ve yetki sınırları: CSRF başlığı olmadan `403 csrf_invalid`, anonim isteklerde `401 unauthorized`, geçici `site_manager` kullanıcısı ile Owner'a ait sertifikaların listelenememesi ve `verify-tls`/`reload-outcome` isteklerinin `403/404` ile reddedilmesi.
  4. Bulgu 1 (`test.fail`): `/websites/:id/ssl` sekmesinde canlı sunulan sertifika (`verify-tls`) göstergesi ve kimlik detaylarının (issuer, fingerprint) varsayılan görünümde sunulmaması.
  5. Bulgu 2 (`test.fail`): `NotificationCenterDrawer` içinde kısmi servis reload durumunda Sistem Uyarıları altında uyarı kartı üretilmemesi.
- Kaynak temizliği: Testte açılan web sitesi ve kullanıcılar `afterAll` hook'unda hem UI hem API sweep adımlarıyla temizlendi; `.28` sunucusunda test önekine ait artık kalmadığı doğrulandı.
