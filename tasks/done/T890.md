## Yapılanlar

- Yalnız `POST provisioning/continue` HTTP 409 + `site_mutation_locked` sonucunda aynı operation GET ile tekrar okunup en fazla 10 sınırlı deneme yapılır. Bu hata, continuation çalışmadan site kilidinde reddedildiğini gösterir.
- Bilinmeyen transport sonucunda aynı aşamaya kör mutation tekrarı yok. Gerçek HTTP 400/403, assertion, failed/blocked required step ve final ready kontrolleri aynen hata verir. Generic store busy veya başka kodlar başarı sayılmaz.
- Devam aşaması, yalnız updatedAt yerine gerçek step durumlarıyla takip edilir. Başka dosya veya ürün kodu değişmedi.

## Doğrulama

- Kaynak/lint geçti. Önceki T886 normal API ve UI koşuları aynı 409 hatasını tekrar üretmişti; ek taze kontrol her koşuda çakışma üretmediği için bu kanıt silinmedi.
- Düzeltilmiş gerçek API PHP koşusunda `site_mutation_locked` bir kez yaşandı, authoritative read sonrası aynı operation tamamlandı. Upload/read/exact HTTP marker/delete, normal removal, üç kayıt 404 ve fiziksel yokluk geçti.
- Ayrı yeni run ile normal gerçek UI statik create, otomatik final ready, gerçek HTTP marker, normal kaldırma ve fiziksel yokluk geçti.
- Gerçek CSRF 403 ve geçersiz source 400 girişleri hâlâ reddedildi; create POST gönderilmedi. Çıktılar özel `.local/t890-smoke/` run ledger ve proof dosyalarında.

## Sınırlar ve açıklama

- Yalnız polling deneyi metadata sonrasında ilerlemedi: creation kaydı ilk continuation aktörünü henüz taşımıyordu. Bu deney başarı sayılmadı, normal panel cleanup ve fiziksel yokluk doğrulandı. İlk başarılı continue çağrısı aktörü kaydeder, sonra worker ilerler.
