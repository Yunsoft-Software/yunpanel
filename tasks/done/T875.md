## 1. Problem ve Kök Neden Analizi
- T864 sonrası sunucuda otomatik Let's Encrypt / self-signed SSL sertifikası üretimi ve provisioning adımı devreye girdiğinden, `web-05.spec.js` ilk testinde oluşturulan `primaryDomain` otomatik olarak yönetilen sertifikaya (`httpsMode: 'managed'` ve geçerli `certificateId`) sahip olmaktaydı.
- İkinci test olan *"hatalı girdi ve sınır durumu: SSL olmadan HTTPS uyarısı ve form sınır değer kontrolü"* testi, ilk testte oluşturulan siteyi kullanıyordu. Sitede zaten sertifika takılı olduğu için `DomainHostingPanel.jsx` üzerindeki `HTTP → HTTPS yönlendirmesinden önce SSL/TLS ekranında HTTPS yapılandırın` veya `SSL sertifikası bağlı değil` uyarıları render edilmiyor ve test `toBeVisible()` adımında düşüyordu.
- Ayrıca anlık Nginx yeniden yüklemeleri veya soket dalgalanmalarında `page.request.get` doğrudan fırlatarak `expect.poll` akışını kırabiliyordu.

---

## 2. Yapılan Değişiklikler
- **`e2e/ozellik/web-05.spec.js`:**
  - İkinci test için HTTPS kapalı (`httpsMode: 'off'` / "Şimdilik HTTP") izole bir test sitesi (`tweb05nossl-a${agentN}-...`) oluşturuldu.
  - Sitede SSL sertifikası bulunmadığından ve `httpsMode === 'off'` olduğundan, barındırma ayarları sayfasında beklenen SSL/HTTPS uyarısı (`/SSL sertifikası bağlı değil|HTTP → HTTPS yönlendirmesinden önce/i`) başarıyla doğrulandı.
  - Form sınır değer kontrolleri (yabancı domain içermeme, max body size > 1024 HTML5 validasyonu, min body size < 0 validasyonu) eksiksiz korundu.
  - Test sunucusunda soket kopmalarına karşı `expect.poll` içindeki API çağrıları `try/catch` ile dayanıklı hale getirildi.
  - Test sonunda ve `afterAll` hook'unda oluşturulan no-SSL test sitesinin panel arayüzü (`deleteDomain`) üzerinden güvenli şekilde silinmesi sağlandı.
