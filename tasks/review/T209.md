# T209 — Manuel test: WP-05 — Yedek/restore, bakım ve arama motoru indeksleme ayarları
Yapan: AGENT_2 · Teslim: 2026-10-28 12:51

## Yapılanlar
- WP-05 özelliği için `e2e/ozellik/wp-05.spec.js` senaryosu gerçek panele ve canlı test sunucusuna (`yunpanel-test`) karşı sıfır mock/stub ile yazıldı.
- 1 mutlu yol senaryosunda Web Siteleri arayüzünde WordPress kurulu hedef sitenin (`yp-wp.webrich.news`) varlığı, site WordPress sekmesi, "Kurulu" rozeti, "Yedekler ve geri yükleme" butonunun varlığı ve tıklandığında `/websites/:id/backup` sayfasına yönlenerek "Yedekleme ve Geri Yükleme", "Yedek al" butonu ve yedek seti özet bilgilerini göstermesi doğrulandı.
- Gerçek API üzerinden kaynak sitenin (`af2e0dfc-2e63-5bdb-b6f2-68bee01bafa7`) `/api/panel/websites/:id/wordpress` (kurulu, primaryDomain, DB listesi), `/api/panel/websites/:id/backups` (backupSet ve DB binding'leri) ve `/api/panel/websites/:id/backup-set` yanıtları doğrulandı.
- Canlı sunucuda SSH ile fiziksel kanıtlar alındı:
  1. Hedef sitede (`yp-wp.webrich.news`) WP-CLI ile `option get blog_public` değerinin `'1'` olduğu,
  2. WP-CLI ile `maintenance-mode status` çıktısının `'Maintenance mode is not active'` olduğu,
  3. WordPress kök dizininde `.maintenance` dosyasının bulunmadığı (`test ! -f .../public/.maintenance`),
  4. Canlı HTTP üzerinden `https://157.180.11.28/robots.txt` adresinden `User-agent: *` ve `Disallow: /wp-admin/` kurallarının döndüğü,
  5. `non-reseller-capabilities.js` envanterinde WP-05 yeteneğinin `completed` statüsünde ve `Linux / Restic / WP Maintenance` ile kayıtlı olduğu kanıtlandı.
- 1 hatalı girdi senaryosunda:
  1. WordPress preview uç noktasına geçersiz bakım aksiyonu (`options.action = 'maintenance.toggle'`) gönderildiğinde 400 Bad Request (`wordpress_action_invalid`),
  2. Desteklenmeyen yedek aksiyonu (`options.action = 'backup.now'`) gönderildiğinde 400 Bad Request (`wordpress_action_invalid`),
  3. Geçersiz repositoryId ile backup preview çağrıldığında 400/404/500 hatası,
  4. Geçersiz repositoryId ve snapshotId ile restore preview çağrıldığında 400/404/500 hatası,
  5. `non-reseller-capabilities.js` içinde beyan edilen ancak router'da bulunmayan `/api/panel/websites/:id/maintenance` uç noktasına yapılan çağrının 404 Not Found döndüğü doğrulandı.
- Plesk eşdeğeri eksiklikler `test.fail` ile işaretlendi:
  1. Plesk WP Toolkit özel bakım modu (Maintenance Mode) geçişi ve özelleştirilebilir şablon arayüzü: WordPress kartında bağımsız bakım modu anahtarı ve özel şablon (countdown timer, sosyal ağlar, özel metin) bulunmamaktadır.
  2. Plesk WP Toolkit tek tıkla arama motoru indeksleme (Search Engine Indexing / blog_public) açma/kapatma anahtarı: WordPress kartında doğrudan indeksleme anahtarı bulunmamaktadır (yalnızca staging klonlama sırasında otomatik kapatılmaktadır).
  3. Plesk WP Toolkit WordPress özelinde tek tıkla Back Up / Restore modalı: WordPress panelinde bağımsız yedek/restore modalı yerine genel site yedek sayfasına yönlendirilmektedir.
- `docs/manuel-test/WP-05.md` raporu oluşturuldu (32 satır, <= 40 kuralına uygun).
- Test 2 kez ardışık koşturularak kararlılığı kanıtlandı (1. koşu 1.4m, 2. koşu 1.2m, 5 passed).
- `afterAll` hook'unda canlı sistem ve veri tabanında hiçbir artık bırakılmadığı (0 artık ilkesi) doğrulandı.
